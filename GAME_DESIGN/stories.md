### 거주 가능 행성 조사 이벤트 — 1차 구현

- 사용자 제공 ZIP의 발견문·조사 방향·기본 보상을 그대로 사용한다. 이벤트 80개, 효과 843행, 확률 7행을 `data/habitableEvents.json`의 `events`, `effects`, `probabilities`로 변환했다. ID 및 모든 원본 행을 보존하고 숫자 필드만 숫자형으로 바꿨다. TSV를 런타임에 파싱하거나 효과 설명 문자열에서 수치를 추출하지 않는다.
- `event_id`로 설명을 조회하고 `(event_id, route, outcome)`으로 결과 효과 전부를 연결한다. 추가 설정은 자원 매핑과 탐험 연구 최대 레벨 2다. 원본 TSV 대신 JSON을 수정한 뒤 빌드한다. 확률·연구 보정·배율도 JSON의 원본 확률 행에서 관리한다.
- 자원 매핑: `energy→energy`, `minerals→mineral`, `food→food`, `consumer_goods→consumer`, `advanced_materials→alloy`, `research→research`.
- 흐름은 발견 스토리(intro) → A/B 조사 방향(route) → 선택 방향의 스토리(routeStory) → 안전/일반/위험 조사(method) → 결과 확인(result)이다. 각 스토리는 계속 버튼으로 넘긴다. 방향 선택 버튼에는 원본 이름과 해당 방향 스토리를 표시한다. 호버 또는 키보드 포커스 시 관련 자원·건설·성장 항목명만 간단히 공개하고, 조사 방식 단계에서는 호버/포커스 시 실제 연구 레벨과 배율을 반영한 확률·복합 효과 수치를 표시한다. 선택지에 보상 수치를 상시 나열하지 않으며 결과 단계에서는 실제 적용 효과를 표시한다.
- 이벤트 ID와 판정 난수는 게임 시드·성계 ID·행성 인덱스로 결정해 이벤트에 저장한다. 거주 가능 행성의 `biome`은 초원·사막·정글·빙하·화산 중 하나로, 별도 시드 난수로 균등 배정해 저장한다. 같은 환경 및 공통 이벤트만 후보로 사용하며 전체 80개 무조건 선택은 폐기한다. 공통은 행성 환경이 아닌 모든 환경에서 가능한 이벤트 분류다. 환경은 이벤트 선정과 정보 표시에만 사용하며 경제 수치·배경 일러스트·기존 지도 생성 난수는 변경하지 않는다.

| 조사 방식 | 대성공 | 일반 성공 | 실패 | 효과 배율 |
| --- | ---: | ---: | ---: | --- |
| 안전 | — | — | — | guaranteed 100%, 일회성 자원만, 영구 특성 없음 |
| 일반 | 15% | 70% | 15% | 모든 결과 ×1 |
| 위험 | 40% | 20% | 40% | 대성공 ×1.5, 일반 ×1, 실패 ×1.25 |

- 탐험 연구 레벨당 대성공 +5%p, 실패 −5%p이며 일반 성공 확률은 유지한다. 안전 조사는 연구 영향을 받지 않는다. 완료한 행성 조사 기술 I·II에서 레벨 0~2를 도출한다. 기존 저장의 레벨은 해당 기술 및 필수 선행 완료로 이관한다. pending 이벤트는 발견 당시 연구 레벨과 기존 고정 난수를 유지해 이후 연구로 판정이 바뀌지 않는다.
- 위험 배율은 해당 결과의 모든 수치에 부호를 유지한 채 적용한다. 대성공에 포함된 불이익도 ×1.5다. 원본 예: 연구 +16%, 광물 −6%는 +24%, −9%가 된다. 연구 레벨은 보상 크기를 바꾸지 않는다.
- 일회성 효과는 제국 자원에 즉시 지급한다. 영구 효과는 해당 행성 `habData.explorationTraits`에 ID·표시명·효과 배열로 보관한다. 미개척 행성에서 얻은 특성도 개척 후 유지되며 다른 행성에는 영향을 주지 않는다.
- 소유한 거주 가능 행성의 정보 패널과 미개척 거주 가능 행성 정보 팝업에서 영구 특성의 제목·복합 효과를 확인할 수 있다.
- 첨부된 `stories.tsv`의 80개 스토리는 `data/habitableStories.json`의 `stories` 배열로 변환해 `event_id`로 연결한다. `story_intro`, `route_a_story`, `route_b_story` 원문을 그대로 보존한다. 기존 이벤트·효과·확률 데이터는 별도 `habitableEvents.json`에 유지한다.
- 팝업은 짙은 SF 배경·금색 이중 프레임·중앙 제목과 상단 일러스트 영역으로 구성한다. 이미지가 없으면 빈 장식 영역을 유지하며 각 스토리의 선택적 illustration 경로로 이미지를 연결한다. 버튼은 호버/키보드 포커스 때 밝은 금색으로 강조한다. 하단 정보 공간을 미리 확보해 호버 시 선택지 위치가 밀리지 않도록 한다. 스토리 원문에는 넓은 행간과 문단 여백을 적용한다. 이벤트 진행 중 작동하지 않던 닫기 버튼은 이 창에서 숨긴다. 기존 선택 단계에 재진입하는 저장도 해당 발견/방향 스토리를 함께 볼 수 있다. 새 스토리 단계는 이벤트의 stage에 저장되어 불러온 위치부터 이어진다.
